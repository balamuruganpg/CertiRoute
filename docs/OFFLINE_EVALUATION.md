# Learned router and offline fixture evaluation

For the new 100-example public paired-output dataset, use the
[GSM8K pilot instructions](GSM8K_PILOT.md). The sections below describe the
original synthetic smoke test, which remains available unchanged.

The default router is now a trained logistic classifier, not a fixed length rule.
This path uses only checked-in local fixtures. It makes no external requests,
needs no keys, and costs nothing to execute beyond local compute.

## Run the complete pipeline

From the repository root, using the already installed environment:

```powershell
.\.venv\Scripts\python -m eval.offline --out results/my-offline-run
```

Or `uv run python -m eval.offline --out results/my-offline-run` if dependencies
are already synced. The pipeline needs no new libraries or embedding downloads.
Choose a new output directory for each run; existing artifacts are not overwritten.

Defaults are `data/eval/sample.jsonl`, `configs/offline.yaml`,
`configs/pricing.fixture.yaml` and seed 42. All can be supplied with `--input`,
`--config`, `--pricing`, `--seed` and `--out`. The fixture runner requires fixture
model IDs; its artifacts must not be reused for real providers.

The existing [saved run](../results/offline-learned/REPORT.md) reports all four
predeclared epsilon values, along with cheap-only and strong-only baselines.
Quality is exact-match accuracy. Risk is mean clipped regret relative to strong.
Costs are the selected tier's input/output token counts times dated hypothetical
prices, not measured API spend.

## What is learned

Features are character count, word count, digit fraction, plus signs,
multiplication signs, code markers and line count. No answer, reference label,
record id or cheap-model generation is available to the predictor at serving time.
The target is `q_cheap >= q_strong`, equivalent to zero clipped regret.

The trainer computes means/scales on `D_router`, then minimizes L2-regularized
logistic loss using deterministic full-batch gradient descent. It fixes 1,500
iterations, learning rate 0.1 and L2 penalty 0.01 before calibration. It requires
both target classes; it does not silently replace a failed fit with a heuristic.
There is no calibration/test-based tuning. The coefficients, intercept, scaler,
feature version, training hash, settings and hashed prompt fingerprints are
exported to plain JSON. Inference requires only Python's standard library.

The model file is hashed, and calibration records that exact learned-model hash.
Missing/corrupt/mismatched weights preserve strong-only serving and readiness 503.
Models load once at startup; changing weights requires recalibration and restart.
`length_v1` remains an explicit legacy baseline, but the default is
`logistic_surface_v1`.

## Data and leakage controls

The 240 records are intentionally learnable arithmetic simulations, generated by
`eval.make_fixture`. Paired outputs, token counts and pricing are synthetic.
Quality labels are verified against the recorded output and expected answer
when loading the fixture; they are not merely trusted annotations.

Before splitting, exact/lexical near duplicates are removed using token-trigram
Jaccard similarity >= 0.9. The runner sorts by a hash of seed plus prompt, never
outcomes, then assigns 40% to router training, 40% to calibration and 20% to test.
The saved run has 96/96/48 records, with no dropped duplicates. This is consistent
with EVALUATION.md's 40% `D_router`, 60% `D_pool`; this first pilot divides that pool
into one calibration/test partition. The split manifest records every assignment.

Training never reads calibration/test rows. Calibration rejects overlap with
training fingerprints, including whitespace variants. The test set is reserved
until fitting and calibration finish. The lexical guard does not prove absence
of semantic duplicates in future real datasets.

CRC retains `(sum(regret * (score > lambda)) + 1)/(n+1) <= epsilon` and uses
strict `>`; ties go strong. With 96 calibration records, the correction alone is
greater than 0.01, so epsilon 0.01 correctly produces always-strong. The full
grid is reported rather than selecting an attractive epsilon after the run.

## End-to-end replay and outputs

The evaluator starts the actual FastAPI lifespan and invokes authenticated chat
requests for each policy. A custom HTTPX transport supplies the recorded cheap
or strong response selected by the provider adapter. Unknown requests fail;
there is no network fallback. This exercises feature inference, artifact loading,
scope, routing, aliases, provider request construction, response bodies and headers.
Tests additionally forbid the real HTTP transport.

Each run writes:

| File | Purpose |
|---|---|
| `train.json`, `calibration.json`, `test.json` | Disjoint paired-score datasets |
| `split-manifest.json` | IDs, seed, split fractions and duplicate rule |
| `router.json` | Learned coefficients/scaler and training provenance |
| `calibration-artifact.json` | Immutable thresholds and matching model hash |
| `gateway.yaml` | Config pointing at the run's learned/calibration artifacts |
| `results.json` | Every held-out decision plus aggregate quality, regret, cost and escalation |
| `REPORT.md` | Table generated from those aggregates |

Result provenance includes source/config/price/data hashes, seed, Python/package
versions, model identities and artifact id. Git SHA is null when the folder is
not a Git repository; a per-file source-hash manifest is still recorded.
Timestamps/artifact IDs change on rerun; the fixture split, fitted weights and
aggregate metrics are deterministic for the same inputs/seed/code.

The standalone calibration script also works offline with the generated split:

```powershell
.\.venv\Scripts\python -m eval.calibrate --config results/my-offline-run/gateway.yaml --input results/my-offline-run/calibration.json --out results/my-offline-run/recalibrated.json
```

To fit separately, use `python -m eval.fit_router --config <config> --input
<train.json> --out <router.json>` and point `router.artifact` at that new file before
calibration. Never feed the entire fixture to training and then calibrate on it.

## Interpretation

This is a working offline integration experiment, not a real LLM benchmark or
the G1 repeated-split validity suite. It does not establish exchangeability,
real-model accuracy, provider cost savings, latency, drift robustness or the
evaluation plan's MVP success criteria. One small held-out sample is descriptive.
There is no billed spend. Do not use its hypothetical dollar costs as price quotes.

Later, replace simulated pairs with frozen real paired outputs and recorded
provider usage, pin actual model revisions, provide dated real prices, and repeat
fitting/calibration on disjoint data. Run the planned repeated splits, honest
baselines, negative controls and shift studies before claiming guarantee validity.
